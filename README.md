# 双窗迷宫 · Dual Window Maze

一个 Godot 4 小游戏 demo：**一个窗口里并排两个"窗口"**，两边各一个角色，各自只能吃到一半的按键。
两个人都要走到**同一张大迷宫的中心**才能通关。

![普通难度](docs/level2.png)

---

## 玩法

- 窗口左边那一格 = **左半张地图**，右边那一格 = **右半张地图**。
  两张图拼起来就是同一张大迷宫，中心那道缝是**终点**，两个窗口各画了半条虚线。
- 左边角色起始只吃 `W`/`S`（上下），右边角色起始只吃 `A`/`D`（左右）。
- 按 **`E` 交换"移动方式"**：`W`/`S` 改由右窗角色响应，`A`/`D` 改由左窗角色响应。
  **两个角色站在原地不动，换的只是"谁现在能动哪个方向"。**
- 所以想横向挪左窗那个角色，必须先按 `E`；想纵向挪右窗那个，也得先按 `E`。
  两个人都落在中心那道缝上 -> **通关**。

## 操作

| 按键 | 作用 |
| --- | --- |
| `W` / `S` | 上下移动（归属哪一侧由 `E` 决定） |
| `A` / `D` | 左右移动（归属另一侧） |
| `E` | 交换上下/左右两组按键的归属 |
| `R` | 重开一局（重新生成迷宫） |
| `1` / `2` / `3` | 切换难度，会直接开新局 |

角色一格一格走，按住方向键会连续走。到终点后角色被钉住，不会因为再按 `E` 或方向键被带走。

## 难度

| 难度 | 迷宫尺寸 | 追逐者 |
| --- | --- | --- |
| 1 简单 | 13×9 | 无 |
| 2 普通 | 17×11 | 有，每 0.85 秒走一格 |
| 3 困难 | 23×15 | 有，每 0.50 秒走一格 |

追逐者是红色菱形，BFS 走最短路追当前角色。玩家 0.135 秒走一格，明显更快，但走廊只有一格宽，
撞上了就是被堵死 —— 得靠岔路口拉扯。被抓到显示"失败"，按 `R` 重来。

## 公平性（为什么不会被一只追逐者堵死）

最初版本是**完美迷宫**（树结构），任意两点只有一条路，终点还只开了一个口 ——
于是追逐者往终点门口一站，玩家数学上就进不去，这是设计缺陷，不是难度。

现在有追逐者的关卡在生成时做三件事，并且都有断言守着：

1. **终点开三个口**：正对迷宫一道，上下各一道绕过来的侧门。堵住一个还有两个。
2. **打通死胡同**：让每一格至少有 2 个可走邻居，不会被逼进死角。
3. **消除割点**：反复找「拿掉之后起点就到不了终点」的格子，在旁边再开一条绕行通道，
   直到**任何单个格子被占据，起点到终点仍然连通**。

外加一条规则：**追逐者不许踏进终点格**（否则最后一步是必死的）。
这几条合起来意味着：地图上不存在「唯一必经之路」，被追上只可能是跑位失误，不可能是无解。

## 运行

用 Godot **4.7.2**（本机 Steam 版）打开本文件夹的 `project.godot`，F5 直接跑。

命令行：

```powershell
$godot = 'D:\steam\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe'
& $godot --path . -- --level=3        # 直接从困难难度开始
& $godot --path .                     # 正常启动
```

开发用参数（跟在 `--` 后面）：

| 参数 | 作用 |
| --- | --- |
| `--level=N` | 启动时直接选第 N 档难度（1~3） |
| `--capture=D:/x/shot.png` | 跑 0.9 秒后把窗口截图存到该路径并退出 |
| `--selftest` | 跑输入分流/交换/通关/被抓的集成自测，打印结果后退出（返回值 = 失败条数） |

## 工程结构

```
project.godot
main.tscn                  # 顶层 Control + 顶栏 + HBox 里两个 SubViewportContainer
scripts/
  main.gd                  # 输入分流、E 交换、难度、胜负、自测
  panel_world.gd           # 一个窗口的全部内容：画迷宫、角色、追逐者（纯 _draw，无美术资源）
  maze.gd                  # 迷宫生成 + 公平性改造（打通死胡同/消除割点）+ BFS 寻路
tests/
  logic_test.gd            # 连通性 + 割点 + 死胡同 自测（120 组随机种子）
docs/level2.png            # 截图
```

## 实现要点

- **两个窗口**：`SubViewportContainer(stretch=true)` 里套 `SubViewport`，左右各一套。
  每个 `SubViewport` 有独立的 World2D，等于两个互不干扰的画面，尺寸跟着容器自动缩放。
- **按键分流**：`W`/`S` 这组永远表示"上下"，`A`/`D` 永远表示"左右"，
  真正换来换去的是"这组键现在驱动哪个面板"—— 一个 `vertical_panel` 变量就够了（`E` 时 `1 - 它`）。
- **键位映射在代码里建**（`InputMap.add_action`），不用手写 `project.godot` 里的 InputEvent 序列化，
  也好让自测用 `Input.action_press` 直接驱动。
- **画图全靠 `_draw`**：墙/地板是一个个矩形，角色是圆，追逐者是菱形，中文用 `SystemFont`（微软雅黑）。
  整个工程零图片资源，拷走就能跑。
- **终点在大地图中心**：左半张图的终点挖在最右一列，右半张图挖在最左一列，两边隔着缝相对，
  各带三个门（正门 + 上下侧门）。
- **半边地图统一由 `Maze.build_half()` 生成**，游戏和测试走同一个入口，不会出现"测试测的是另一套逻辑"。

## 自测

```powershell
$godot = 'D:\steam\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe'
& $godot --headless --path . --script res://tests/logic_test.gd   # 迷宫/割点/死胡同/寻路
& $godot --headless --path . -- --selftest                        # 输入分流/交换/胜负/追逐者规则
```

`logic_test` 会把每个迷宫里**所有可走格子**逐个拿掉，验证起点仍能摸到终点门，
所以「堵得死」这件事是被穷举过的，不是抽样。当前状态：`logic_test` 120 组随机种子全过；
`--selftest` 20 条断言全过；困难难度开一局生成两张图约 40 ms。
